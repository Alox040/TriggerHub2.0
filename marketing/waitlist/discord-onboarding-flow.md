# Discord Onboarding Flow

## Agent
Implementation Agent

## Aufgabe
Define how accepted alpha testers are onboarded into Discord and prepared to give useful feedback.

## Betroffene Dateien
- `marketing/waitlist/discord-onboarding-flow.md`

## Discord Onboarding Steps
1. Invite Sent
Send a Discord invite plus a short note that TriggerHub is in closed alpha and still maturing core integrations and workflows.

2. Welcome Channel
Show a pinned message with:
- what TriggerHub currently is
- what TriggerHub is not yet
- how feedback should be shared
- where announcements and builds will appear

3. Rules and Expectations
Require confirmation of:
- early-stage prototype expectations
- respectful bug reporting
- willingness to describe workflow context
- no public misrepresentation of unfinished features

4. Setup Intake
Ask each tester to post:
- Windows version
- creator role
- current tool stack
- biggest repeated workflow
- preferred feedback style: async or call-based

5. Channel Routing
Assign roles or tags:
- streamer
- creator-operator
- power-user
- alpha-observer
- active-tester

6. Guided First Task
Give each accepted tester one simple first action:
- describe a workflow
- review a demo
- react to a build note
- share a current workaround

7. Feedback Loop
Direct testers to structured channels:
- `#workflow-pain`
- `#alpha-feedback`
- `#bug-reports`
- `#build-updates`
- `#requests-roadmap`

8. Activation Check
Within 72 hours, confirm whether the user:
- joined successfully
- posted setup context
- engaged with one first task
- signaled realistic expectations

## Discord Onboarding Principles
- Keep onboarding short but explicit.
- Reinforce that TriggerHub is not yet a public-ready broad-market tool.
- Reward high-signal workflow detail over generic praise.
- Treat Discord as both support layer and research surface.

## Risks
- If onboarding sounds like a launch community, users will expect public-product maturity.
- If onboarding is too loose, feedback quality will collapse quickly.
