# Alpha Application Questions

## Agent
Implementation Agent

## Aufgabe
Define the deeper qualification layer used after a strong waitlist submission.

## Betroffene Dateien
- `marketing/waitlist/alpha-application-questions.md`

## Application Purpose
Select alpha testers who match the current closed-alpha product stage and can provide actionable feedback.

## Core Questions
1. Describe one creator workflow you repeat every session that you would want TriggerHub to reduce or automate.
2. Which Windows-based tools are part of that workflow today?
3. Where does that workflow currently break, slow you down, or create stress?
4. What have you already tried to solve this problem?
5. How comfortable are you testing software that still has incomplete integrations and rough UX?
6. How often could you realistically provide feedback in Discord during a closed alpha?
7. Are you more interested in influencing product direction or getting immediate production-ready utility?
8. If TriggerHub solved one part of your workflow first, which part should it be?

## Alpha Tester Selection Criteria
### High Priority
- Clear Windows creator workflow with repeated manual steps
- Tool stack overlaps with TriggerHub's current direction
- Strong willingness to report bugs, edge cases, and workflow gaps
- Comfortable with closed-alpha instability and honest about rough edges
- Can articulate useful outcomes instead of asking for vague “all-in-one” magic

### Medium Priority
- Relevant workflow pain but lower technical comfort
- Strong interest yet limited time for feedback
- Broader creator role with less direct live workflow complexity

### Low Priority
- Wants a polished public product immediately
- Expects complete OBS, Spotify, clip capture, plugin marketplace, or editor flows today
- Unwilling to use Discord or provide structured feedback
- Uses non-Windows setups as primary environment

## Scoring Model
| Criterion | Weight | Notes |
|---|---|---|
| Workflow pain clarity | 25 | Most important qualification factor |
| Windows fit | 15 | Current platform focus |
| Tool-stack relevance | 15 | Align with current product direction |
| Technical comfort | 15 | Useful for prototype testing |
| Feedback reliability | 20 | Needed for closed alpha |
| Expectation realism | 10 | Must understand current product stage |

## Decision Outcomes
- Accept for closed alpha
- Hold for early access nurture
- Reject for now but keep on broader waitlist

## Risiken
- Over-indexing on highly technical users can distort broader creator usability feedback.
- Accepting users with unrealistic expectations will increase churn and support overhead.
